# 兴享智家·慧家中枢接口文档

## 1. 接口设计原则

系统接口围绕比赛要求的 main.run 入口函数设计。外部调用方只需要传入用户自然语言、会话状态和可选配置，即可获得智能体回复、任务规划、工具调用结果、更新后的状态和性能指标。

接口设计目标：

1. 满足比赛规定：入口函数名为 run，入口函数所在程序名为 main。
2. 支持命令行测试、Web Demo、自动化测试脚本复用。
3. 所有工具调用均返回结构化 JSON，方便演示界面展示。
4. 关键动作可解释、可追踪、可复现。

## 2. 主入口接口

### 2.1 函数定义

```python
def run(user_input: str, state: dict | None = None, config: dict | None = None) -> dict:
    """
    兴享智家·慧家中枢主入口函数。

    Args:
        user_input: 用户自然语言输入。
        state: 会话状态，首次调用可为空。
        config: 可选运行配置。

    Returns:
        dict: 智能体执行结果。
    """
```

### 2.2 请求参数

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| user_input | string | 是 | 用户自然语言指令 |
| state | object/null | 否 | 会话上下文，包含用户、场景、历史任务、设备状态摘要等 |
| config | object/null | 否 | 运行配置，如是否启用模型推理、最大工具调用数、调试开关 |

### 2.3 config 字段

| 字段 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| mode | string | "hybrid" | hybrid 表示小模型加规则，rule 表示仅规则后备 |
| max_steps | int | 8 | 单轮最大任务步骤数 |
| require_confirm | bool | true | 是否对敏感动作启用确认 |
| debug | bool | false | 是否返回详细调试信息 |
| language | string | "zh-CN" | 回复语言 |

### 2.5 返回字段说明

| 字段 | 类型 | 说明 |

| tool_results | array | 工具调用结果 |
| state | object | 更新后的会话状态 |
| metrics | object | 性能指标 |

## 3. 意图与槽位规范

### 3.1 意图列表

| 意图名 | 说明 | 示例 |
| --- | --- | --- |
| scene_mode_apply | 应用家庭场景模式 | “切到睡前模式” |
| device_control | 控制智能设备 | “把客厅灯关掉” |
| network_diagnose | 诊断家庭网络 | “卧室 Wi-Fi 有点卡” |
| reminder_create | 创建关怀提醒 | “提醒爷爷九点吃药” |
| reminder_query | 查询提醒状态 | “爷爷今天吃药了吗” |
| knowledge_query | 查询本地知识库 | “空调睡眠模式怎么用” |
| home_status_query | 查询家庭状态 | “家里现在有哪些设备开着” |
| followup_answer | 多轮追问回答 | “先保证爷爷那边” |

### 3.2 通用槽位

| 槽位 | 类型 | 说明 |
| --- | --- | --- |
| room | string | 房间，如客厅、主卧、老人房 |
| member | string | 家庭成员，如爷爷、奶奶、爸爸、妈妈 |
| device | string | 设备，如灯、空调、电视、门锁 |
| action | string | 操作，如打开、关闭、调暗、诊断 |
| time | string | 时间，如今晚九点、睡前、明早八点 |
| scene | string | 场景，如 sleep、away、home、movie |
| priority | string | 优先级，如老人优先、会议优先、儿童优先 |
| condition | string | 条件，如无人、未回应、信号弱 |

## 4. 工具接口

所有工具函数遵循统一结构：

```python
def tool_name(args: dict, context: dict) -> dict:
    return {
        "status": "success",
        "data": {},
        "message": "执行完成"
    }
```

### 4.1 设备控制工具

#### device.control

说明：控制家庭设备状态。

请求：

```json
{
  "device_id": "livingroom_light",
  "action": "set_brightness",
  "value": 30
}
```

响应：

```json
{
  "status": "success",
  "data": {
    "device_id": "livingroom_light",
    "old_state": {"power": "on", "brightness": 80},
    "new_state": {"power": "on", "brightness": 30}
  },
  "message": "客厅灯亮度已调至 30%"
}
```

支持动作：

| action | value | 说明 |
| --- | --- | --- |
| turn_on | null | 打开设备 |
| turn_off | null | 关闭设备 |
| set_brightness | 0-100 | 设置灯光亮度 |
| set_temperature | number | 设置空调温度 |
| set_mode | string | 设置模式 |
| lock | null | 锁门 |
| unlock | null | 解锁，默认需要确认 |

```json
}
```

## 6. 错误码

| 错误码 | 说明 | 处理方式 |
| --- | --- | --- |
| INVALID_INPUT | 输入为空或格式错误 | 提示用户重新输入 |
| UNKNOWN_INTENT | 未识别意图 | 进入澄清追问 |
| SLOT_MISSING | 必要槽位缺失 | 询问缺失信息 |
| TOOL_NOT_FOUND | 工具不存在 | 返回系统配置错误 |
| TOOL_FAILED | 工具执行失败 | 提供失败原因和替代建议 |
| NEED_CONFIRMATION | 需要用户确认 | 暂停执行高风险动作 |
| SAFETY_BLOCKED | 安全策略阻止 | 不执行动作并说明原因 |
