# 兴享智家·慧家中枢实现方案效果

## 1. 方案定位

本方案实现一个运行在端侧设备上的家庭智能体系统。它不是简单的聊天机器人，而是能够理解家庭场景、拆解任务、调用工具、保持多轮状态并给出可解释结果的本地智能中枢。

在初赛 Demo 中，系统通过模拟家庭设备、网络拓扑、家庭成员档案和本地知识库来展示完整闭环。后续可替换为真实硬件接口，接入家庭网关、智能屏、智能家居平台、摄像头、门锁、健康设备等。

## 2. 总体架构

系统采用“轻量模型 + 规则规划器 + 工具注册表 + 本地知识库 + 可视化 Demo”的架构。

```text
用户输入
  |
  v
自然语言理解层
  - 意图识别
  - 槽位抽取
  - 上下文补全
  |
  v
任务规划层
  - 任务拆解
  - 安全检查
  - 工具选择
  - 执行顺序编排
  |
  v
工具执行层
  - 设备控制
  - 网络诊断
  - 提醒管理
  - 家庭档案
  - 知识库检索
  |
  v
状态与记忆层
  - 会话状态
  - 家庭状态
  - 任务日志
  |
  v
结果生成层
  - 自然语言回复
  - 执行摘要
  - 性能指标
```

## 3. 核心实现思路

### 3.1 小模型负责理解，规则负责执行

端侧小模型适合做意图识别、槽位抽取、回复润色和模糊表达理解，但不适合完全自由地决定高风险动作。因此系统采用双层机制：

1. 小模型或规则分类器识别用户意图。
2. 任务规划器把意图转换为标准动作。
3. 工具注册表只允许调用白名单工具。
4. 门锁、摄像头、告警等敏感动作进入安全确认流程。

这样既能体现智能体能力，又能保证 Demo 稳定可控。

### 3.2 本地情境图谱

系统内置一份家庭情境数据，描述家庭成员、房间、设备、网络节点和提醒事项之间的关系。

示例：

```json
{
  "members": {
    "爷爷": {
      "room": "老人房",
      "preferences": {
        "sleep_temperature": 26,
        "night_light": true
      }
    }
  },
  "rooms": {
    "老人房": {
      "devices": ["elderly_room_light", "elderly_room_ac", "elderly_room_camera"],
      "mesh_node": "mesh_2"
    }
  }
}
```

当用户说“先保证爷爷那边”时，系统可以根据情境图谱推断出目标房间是“老人房”，目标网络节点是“mesh_2”。

### 3.3 工具函数模拟真实家庭能力

初赛阶段工具函数先使用模拟数据实现，确保无需真实硬件也能演示完整流程。

计划实现的工具：

1. device.control：模拟控制灯、空调、电视、门锁。
2. scene.apply：批量执行睡前、离家、回家、观影等模式。
3. network.diagnose：模拟 Wi-Fi 信号、延迟、丢包、带宽占用诊断。
4. network.apply_qos：模拟对老人房、会议设备、学习设备设置网络优先级。
5. reminder.create：创建吃药、饮水、休息等提醒。
6. reminder.query：查询提醒完成情况。
7. home_profile.query：查询家庭成员和设备关系。
8. knowledge.search：检索本地家庭知识库。
9. safety.check：判断动作是否需要安全确认。

### 3.4 本地知识库

本地知识库用于回答家庭规则、设备说明和健康注意事项类问题。初赛阶段可以采用 JSON 文档 + 关键词检索或 SQLite + BM25，实现低资源可运行。

示例知识：

1. 睡前不建议饮用浓茶、咖啡等刺激性饮品。
2. 空调睡眠模式会降低风速并逐步调整温度。
3. 老人房夜间默认保留 10% 夜灯亮度。
4. 视频通话卡顿优先检查 RSSI、丢包率和高带宽设备。

### 3.5 性能优化

1. 模型量化：采用 4-bit 或 8-bit 量化降低内存占用。
2. 混合推理：常见意图使用规则快速匹配，复杂表达再调用小模型。
3. 工具结果缓存：家庭档案、设备清单等低频变化数据缓存。
4. 短上下文记忆：只保留最近若干轮关键信息，避免上下文过长。
5. 流式执行日志：工具执行结果即时展示，降低用户等待感。

## 4. Demo 效果设计

### 4.1 主界面效果

Demo 主界面建议采用四区布局：

1. 左侧：家庭智能体对话窗口。
2. 中间：任务规划步骤和工具调用日志。
3. 右侧：设备状态与网络状态面板。
4. 底部：性能指标栏。

用户每输入一句话，界面同步展示：

1. 识别出的意图和槽位。
2. 智能体规划出的任务步骤。
3. 每个工具的调用参数和执行结果。
4. 家庭设备状态变化。
5. 本轮响应耗时、工具耗时和内存估计。

### 4.2 演示场景一：睡前模式

输入：

```text
爸妈准备睡了，帮我切到睡前模式，顺便检查一下门锁。
```

系统表现：

1. 识别意图：scene_mode_apply。
2. 提取槽位：成员=爸妈，场景=睡前，附加任务=门锁检查。
3. 调用 home_profile.query 查询主卧和客厅设备。
4. 调用 scene.apply 关闭电视、调暗灯光、设置空调睡眠模式。
5. 调用 device.control 或 device.query 检查门锁。
6. 输出：“已切换到睡前模式，客厅电视已关闭，主卧空调已设为睡眠模式，门锁已上锁。”

可视化变化：

1. 客厅灯亮度从 80% 变为 20%。
2. 电视从 on 变为 off。
3. 主卧空调模式从 normal 变为 sleep。
4. 门锁显示 locked。

### 4.3 演示场景二：老人房网络诊断

输入：

```text
爷爷房间视频有点卡，帮我看看。
```

系统表现：

1. 识别意图：network_diagnose。
2. 通过家庭档案推断“爷爷房间”为老人房。
3. 调用 network.diagnose 查询 RSSI、延迟、丢包率和带宽占用。
4. 返回诊断：老人房 Mesh 信号偏弱，客厅电视占用较高带宽。
5. 追问：“是否要临时开启老人房视频优先？”

用户继续输入：

```text
先保证爷爷那边。
```

系统表现：

1. 识别为 followup_answer。
2. 继承上一轮网络诊断上下文。
3. 调用 network.apply_qos，将老人房视频通话设为优先。
4. 输出：“已开启老人房视频优先策略，持续 60 分钟。”

可视化变化：

1. 老人房网络状态从 warning 变为 optimized。
2. QoS 策略显示 video_call_first。
3. 客厅电视带宽优先级降低。

### 4.4 演示场景三：吃药提醒

输入：

```text
提醒爷爷晚上九点吃降压药，如果十分钟没回应就再提醒一次。
```

系统表现：

1. 识别意图：reminder_create。
2. 槽位：成员=爷爷，时间=21:00，事项=吃降压药，未回应策略=10 分钟后再提醒。
3. 调用 reminder.create。
4. 输出：“已创建爷爷每天 21:00 的吃药提醒，若 10 分钟内未确认会再次提醒。”

继续输入：

```text
爷爷今天的提醒完成了吗？
```

系统表现：

1. 识别意图：reminder_query。
2. 调用 reminder.query。
3. 输出今天提醒完成情况。

### 4.5 演示场景四：本地知识问答

输入：

```text
爷爷睡前能不能喝浓茶？
```

系统表现：

1. 识别意图：knowledge_query。
2. 调用 knowledge.search 检索本地健康注意事项。
3. 输出：“不建议睡前喝浓茶，可能影响睡眠。可以换成温水。该建议仅供日常健康管理参考。”

可视化变化：

1. 知识库命中文档显示在工具日志中。
2. 明确标注来源为本地知识库。

## 5. 预期性能效果

初赛 Demo 可以给出以下目标指标：

| 指标 | 目标值 | 说明 |
| --- | --- | --- |
| 首次启动时间 | 小于 10 秒 | 规则模式可更快，模型模式取决于设备 |
| 单轮规则推理响应 | 小于 300 ms | 常见意图快速路径 |
| 单轮混合推理响应 | 小于 2 秒 | 含轻量模型推理 |
| 内存占用 | 小于 4GB | 满足赛题端侧约束 |
| 工具调用成功率 | 大于 95% | 基于模拟工具和结构化参数 |
| 多轮上下文轮数 | 5-10 轮 | 保留关键状态摘要 |
| 本地知识检索耗时 | 小于 100 ms | 小规模知识库 |

## 6. 与评分规则的对应关系

### 6.1 创新

1. 不只是智能家居控制，而是把家庭网络自愈、老人关怀、设备联动和本地知识库统一到端侧 Agent。
2. 通过家庭情境图谱理解“爷爷那边”“睡前”“卧室视频卡”等场景化表达。
3. 使用双脑架构，让小模型负责理解，让规则规划器保证执行稳定。

### 6.2 价值

1. 可应用于家庭网关、智能屏、路由器、家庭机器人等真实终端。
2. 解决家庭设备割裂、网络问题难定位、老人关怀弱上下文等现实痛点。
3. 适合运营商和终端厂商作为家庭 AI 服务入口。

### 6.3 成本

1. 使用轻量模型或规则后备模式，降低端侧部署成本。
2. 本地知识库和模拟工具均可低资源运行。
3. 不依赖云端敏感数据传输，降低服务成本和隐私风险。

### 6.4 演示

1. 提供可运行代码。
2. 提供可视化 Demo。
3. 展示多轮对话、任务规划、工具调用、状态变化和性能指标。
4. 支持没有真实硬件时的完整仿真演示。

### 6.5 文档

1. 需求、接口、方案效果文档完整。
2. 后续可继续补充系统架构、算法说明、部署说明和测试报告。
3. 文档结构与比赛提交要求一致，方便整理为 PDF。

## 9. 最终呈现效果

完成后，评委看到的效果应是：

1. 用户能像和家庭管家说话一样下达复杂指令。
2. 系统能把一句话拆成多个明确任务。
3. 每个任务都能调用可解释的工具函数。
4. 家庭设备和网络状态会随工具执行发生变化。
5. 多轮对话不是简单问答，而是能延续上一轮任务上下文。
6. 健康、家庭、设备信息来自本地知识库和本地状态。
7. 系统能展示端侧低资源运行的性能数据。
